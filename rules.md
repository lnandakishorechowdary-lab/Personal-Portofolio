# Build Rules

## Content

- Use only information provided in the project.
- Do not invent achievements.
- Do not invent testimonials.
- Do not invent clients.
- Do not invent awards.
- Do not invent certifications.
- Keep project descriptions factual.

## Design

- Follow design.md.
- Keep the interface readable.
- Maintain clear visual hierarchy.
- Maintain sufficient contrast.
- Avoid unnecessary decoration.
- Avoid generic AI-generated patterns.

## Responsive Behaviour

- Do not allow unwanted horizontal overflow.
- Keep important actions usable on small screens.
- Preserve readable text.
- Test mobile, tablet and desktop layouts.

## Development

- Make changes in understandable steps.
- Do not rewrite the entire project unnecessarily.
- Review major changes.
- Test meaningful changes before continuing.
- Preserve working functionality.

## Navigation

- Navigation links must point to existing sections.
- Active section should update correctly.
- Mobile menu must open and close correctly.

## Code

- Reuse existing components where possible.
- Avoid unnecessary dependencies.
- Keep components understandable.
- Do not remove working code without a reason.
